# Measurement exports and saved history

NeonTrace JSON exports use application schema version **1**. The top-level object contains `schema_version`, `app_version`, `exported_unix_ms`, `demonstration`, `notes`, `data_credits`, and `sessions`. Timestamp fields are milliseconds since the Unix epoch, in UTC. Missing values are JSON `null`; an unavailable location does not imply a missing network reply.

Each session identifies its target, pinned endpoint address and family, DNS candidates, generation, start/end times, route observation time, route completion, destination reachability, and demonstration status. `origin` and `endpoint` hold optional geographical estimates. `hops` keeps all responding addresses observed at each TTL, including alternate interfaces and nonresponse counts. `pings` and `tcp_checks` hold endpoint measurements separately. `route_snapshots` retains previous coherent routes independently, with each observation timestamp, completion/reached flags and hop observations; the UI bounds this list to sixteen. `errors` retains structured diagnostic codes with timestamps. TCP connection time is separate from ICMP RTT.

`trace_complete` means the bounded trace attempt finished; `destination_reached` states whether it obtained a destination response. A completed attempt can therefore remain incomplete as a route. Every hop RTT is a round trip from the measuring computer. Animation progress and the eight-second presentation timeline are never substituted for measurements.

CSV uses a long-form table. The `row_kind` column distinguishes `target`, `origin`, `hop`, `ping`, `tcp`, and `diagnostic`, and archived `route_snapshot` rows. The `route_snapshot` column separates current hop rows from older coherent route observations. Every configured target receives a `target` row even when no probe replies. Each responding interface produces its own hop row. Silent hops retain a row with their actual status and no invented address or coordinates. Repeated target ID and generation columns keep concurrent sessions distinct. Optional values are empty cells; `unknown_location` explicitly identifies absent point estimates. Provider and database edition fields retain geolocation provenance. JSON retains the richer nested structure.

The displayed min/average/max use only successful, finite, nonnegative endpoint RTTs. Jitter is the mean absolute change between consecutive successful RTTs; a missing or invalid sample breaks adjacency. It is not a link delay or a traceroute metric.

History is disabled by default. Ordinary settings do not contain target names, IP addresses, route sessions, theme overrides, animation speed, or manual origin data. Enabling history permits explicit snapshot recording, limited to the newest 100 records and 32 MiB combined; one record cannot exceed 8 MiB. Users can delete individual saved records or clear them. Disabling history stops recording and retains earlier saved records until deleted.
